# Node-RED Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
IoT/automation-энтузиаст или инженер, использующий self-hosted Node-RED как визуальный
конструктор потоков данных (популярен в связке с Home Assistant и промышленным IoT).

## 2. Момент истины после подключения
Сразу после `connect_node_red` (с SSRF-защищённой валидацией self-hosted адреса) — список
развёрнутых flows с их статусом (активен/остановлен).

## 3. Что пользователь видит
- Flows (визуальные потоки обработки данных) целиком со всеми узлами — `list_flows`,
  `get_flow`.
- Узлы (nodes), установленные в инстансе (какие интеграции доступны) — `list_installed_nodes`.
- Логи выполнения flow (debug-вывод) — `get_debug_log`.
- Контекст выполнения (переменные, сохранённые между запусками) — `get_flow_context`.
- Статус самого runtime (версия Node-RED, время работы) — `get_runtime_info`.

## 4. Чем пользователь может управлять
- Разворачивать (deploy) новую/изменённую версию flow — `deploy_flow`.
- Включать/отключать flow — `enable_flow`, `disable_flow`.
- Инжектировать сообщение вручную в flow для теста — `inject_message`.
- Устанавливать новый узел (node) из палитры — `install_node`.
- Перезапускать runtime, если нужно применить системные изменения — `restart_runtime`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'какие flows у меня сейчас отключены на моём Node-RED?'. Она
находит через `list_flows`, а я прошу развернуть исправленную версию — `deploy_flow`
делает это на self-hosted инстансе без открытия Node-RED редактора в браузере."

## 6. Что делает это "заточенным под него"
Работает с self-hosted инстансом клиента напрямую (с SSRF-защитой) — Node-RED почти
всегда развёрнут локально (Raspberry Pi, домашний сервер, промышленный шлюз), и
безопасная работа именно с ЕГО адресом — ключевое требование.
